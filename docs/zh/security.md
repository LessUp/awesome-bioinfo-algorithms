## 支持的版本

我们为安全漏洞发布补丁。哪些版本符合条件？

| 版本 | 支持状态 |
|:--------|:----------|
| 1.0.x   | ✅ 支持    |

始终使用最新版本以确保您收到安全更新。

## 报告漏洞

{: .warning }
**请不要通过公共 GitHub issue 报告安全漏洞。**

请通过以下方式报告：

### 邮件
发送邮件至：**security@lessup.org**

### GitHub 安全公告
1. 进入仓库 Security 标签页
2. 点击 "Report a vulnerability"
3. 填写漏洞报告表单

### 报告内容

您的报告应包含：

1. **描述** — 漏洞的清晰描述
2. **影响** — 可被利用的内容和潜在影响
3. **复现步骤** — 复现漏洞的逐步说明
4. **受影响版本** — 哪些版本受影响
5. **建议修复** —（可选）您的修复建议

---

## 响应流程

收到安全报告后，我们遵循以下流程：

| 阶段 | 时间线 | 行动 |
|:------|:---------|:--------|
| 确认收到 | 48 小时内 | 确认收到报告 |
| 评估 | 1 周内 | 评估严重性和影响 |
| 补丁开发 | 视严重性而定 | 开发和测试修复 |
| 披露 | 修复发布后 | 发布安全公告 |

### 沟通

- 我们会通知您我们的进展
- 如有需要可能向您询问更多信息
- 您将在安全公告中被致谢（除非您希望匿名）

---

## 披露政策

收到安全漏洞报告后，我们将：

1. 确认问题并确定受影响版本
2. 审计代码查找类似问题
3. 为所有支持版本准备修复
4. 尽快发布新版本
5. 在 GitHub 上发布安全公告

---

## 安全最佳实践

### 对于用户

- 始终使用最新版本
- 使用 `python -m awesome_bioinfo validate` 验证算法数据
- 未经验证不要手动修改数据文件
- 开发时使用虚拟环境

### 对于贡献者

- 永远不要提交密钥或凭证
- 添加新算法时验证所有输入
- 严格遵循 YAML 模式
- 提交 PR 前运行验证

## 范围

### 在范围内

- `scripts/` 中的 Python 代码
- 数据验证逻辑
- CLI 工具安全
- 文档安全

### 不在范围内

- 第三方依赖（向其维护者报告）
- 我们链接到的算法实现
- GitHub 基础设施（向 GitHub 报告）
